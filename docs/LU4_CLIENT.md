# LU4 client

The servers also serve the LU4 (Liberta Ultimata 4) client, an Unreal
Engine 5 client of Lineage II, next to the usual client. This branch,
`Cliente-18-10-2026`, is for the **`lu4.bin`** build of 18-10-2026, which logs
in without any DLL through
[lu4loader](https://github.com/luannbr/Open_LU4_login_serverlist_dll/tree/Cliente-18-10-2026).
The earlier `lu4-win64-shipping.exe` build with the injected
`lu4authhook.dll` is served by the `main` branch.

## Login

The client is protected and three parts of its login can't be produced by an
emulator, so the server and the loader meet halfway:

| Part | Official service | This server |
| --- | --- | --- |
| Init packet | 21-byte message with the session Blowfish key | 37-byte message: `lu4.bin` reads the key at bytes 21..36 |
| Session key | derived from the Init | fixed: `BC AF 64 50 71 3E 25 CF E1 72 C2 F4 BE BE 39 B2`, expanded in `AuthGateD/etc/lu4_auth_key.bin` |
| Reply signature | 32-byte Ed25519 signature after every reply | the marker `LU4-MAGIC-SERVERLIST-MAC-BYPASS!`, accepted by the loader |
| Account and password | RSA block in the login packet | sent by the loader to AuthD's validator |

The flow:

1. The loader starts `lu4.bin`, patches the client's 32-byte signature
   compare to accept the marker and sends `AUTH\t<account>\t<password>\n` to
   AuthD on `Lu4ValidatorPort` (27110). AuthD checks the account and keeps the
   pair for the sender's IP. The loader sends it again every 2 minutes, and
   the pair stays usable for its whole time to live, so the client can log in
   again without being restarted.
2. The client connects to AuthGateD's `lu4Port` (2107). AuthGateD sends the
   37-byte Init (`kInitHex` in `AuthGateD/src/Lu4Login.cpp`), decrypts the
   login with the fixed key and forwards it to AuthD with the account
   `\x7fLU4`.
3. AuthD replaces that account with the pair stored for the client's IP and
   logs it in as usual. The server list and the play reply carry the marker
   in place of the signature.

Without the 37-byte Init the client installs a different key and the login
decrypts to garbage (opcode 255), whatever the loader does.

### Rebuilding the Init

`tools/client/lu4_init.py` prints `kInitHex`. It decodes the official Init,
checks that it re-encodes it byte for byte, and encodes the 37-byte message
with the marker and the S half of the official signature (which keeps S
below the Ed25519 group order). It needs only Python 3.

```bash
python tools/client/lu4_init.py
```

## Configuration

| File | Option | Value | Meaning |
| --- | --- | --- | --- |
| `AuthD/etc/config.txt` | `Lu4Mode` | `true` | LU4 login and the credential validator |
| `AuthD/etc/config.txt` | `Lu4ValidatorPort` | `27110` | validator port the loader connects to |
| `AuthD/etc/serverlist` | game port | `7778` | port the server list sends to the client |
| `AuthGateD/etc/config.txt` | `lu4Port` | `2107` | LU4 client login; `0` disables it |
| `AuthGateD/etc/config.txt` | `serverPort` | `2206` | the usual client's login (unchanged by LU4) |
| `L2Server/etc/l2server.ini` | `UserPort` | `7778` | game port; must match the server list |
| `L2Server/etc/l2server.ini` | `reconnectAuth` | `1` | reconnect to AuthD and re-sync players instead of stopping |
| `L2Server/etc/l2server.ini` | `InterludeKarma` | `true` | Interlude karma rules (below) |

The ports 2206 and 7778 replace 2106 and 7777, which other programs used on
the development machine. `scripts/start-all.ps1` reads the ports from these
files, so any value works.

`lu4Port` also needs `AuthGateD/etc/lu4_auth_key.bin`. The client always
connects to `185.29.255.102:2108`. In local development the loader (as
Administrator) adds that address as a loopback alias and a `netsh` portproxy
from port 2108 to `lu4Port`; in production that address must reach
`lu4Port`.

## Game server

L2Server recognises an LU4 connection by its version packet; no option is
needed. `L2Server/src/Portable/Lu4Protocol.cpp` translates the packets both
ways: the client's packets into the server's, and the server's into the
layouts the LU4 client reads (taken from its packet readers, its captures
and the Lucera port). NPC names and speech come from
`L2Server/etc/lu4_npcname.txt` and `lu4_npcstring.txt`, generated by
`tools/client/lu4_npc_tables.py`.

Working with LU4: login, character selection and creation, movement, NPCs,
combat, inventory and skills, chat, other players, party, trade, private
stores, NPC shops, multisell, ground items, resurrection, soulshots and auto
soulshots, NPC speech, PvP flag and karma colours. Not yet translated: quests,
macros, henna, friends, recipes, mail, clans, warehouse, enchanting,
gatekeepers, Olympiad and sieges, among others.

### Interlude karma

With `InterludeKarma=true` (`[Setting]` in `l2server.ini`) the server keeps
Interlude rules on top of its reputation system: there is no reputation above
zero (a stored positive value counts as 0), and killing a player killer
counts as a PvP kill instead of raising the killer's reputation. Player
kills, karma loss from hunting and karma loss on death are unchanged. The LU4
client shows karma as a positive number; the translation turns reputation
`-N` into karma `N`.

## Start order

As usual: AuthD, AuthGateD, CacheD, L2Server, L2NPC
(`scripts/start-all.ps1`). Then run the loader on the client machine.
